### 1. Web 工具：搜索 + 网页阅读

- [x] **位置**：`extensions/_lib/webtools.py`（新内核库）、`src/sharedlib.rs`
  （LIBS 清单注册 loquat_webtools）、`extensions/chat/plugin.py`（工具声明与配置）
- **问题**：LLM 闭卷——时间以外的任何现实信息（新闻/价格/文档/天气）一概不知，
  群里甩个链接也读不了。工具面原有 6 个（now/system_status/send_message/recall/
  poke/react）全部不产生新信息
- **修法**：新增内核库 webtools.py（标准库 urllib + html.parser，不引第三方依赖，
  与 llm.py 同约定）：`search(query)` 双 provider——duckduckgo（HTML 结果页解析，
  免 key）默认、bocha（API key，国内直连）；`fetch(url)` 抓网页抽正文
  （script/style 剔除、块级断行、空白归并、2MB 下载上限、4k 字符输出截断）。
  网络与解析分离：解析是纯函数，fixture 单测不打网。chat 插件声明
  web_search / read_webpage 两个工具 + search_provider/search_api_key 配置
- **验证**：cargo test：DDG 结果页 fixture 解析（uddg 跳转还原、摘要按文档序配对、
  直链保留）、HTML 抽正文（script/style 剔除、空行归并）；`just lint` 全绿。
  真实搜索与读网页连 QQ 后人工复测
- **状态**：✅ 已完成（2026-10-23）：webtools.py 按「搜索多 provider + 抓页抽正文」
  实现，LIBS 注册 loquat_webtools（5 库，依赖序 log 最先不变）；chat 插件新增
  web_search / read_webpage 工具与 search_provider（options 限定）/search_api_key
  配置。新增测试 webtools_parses_ddg_and_extracts_text（tests_webtools.rs，
  fixture 内联不触网，覆盖 DDG 解析、DeepSeek 应答解析、api_base 规整、HTML
  抽正文）。同日追加：应用户要求默认 provider 定为 deepseek——官方
  Search/Fetch API（POST /v1/tools/search、/v1/tools/fetch，复用 LLM 的
  api_key，国内直连，按成功次数计费 5 元/千次，Search 100 QPS / Fetch 25 QPS），
  摘要优先取 summary（官方给模型消费的长摘要）并清洗 markdown 转义残留，
  read_webpage 在 deepseek 通道下走官方 Fetch 返回 Markdown；duckduckgo /
  bocha 保留为备选。真机冒烟（真实 key）：搜索与抓页均通，「今天 上海 天气」
  返回中央气象台实时数据

### 2. 识图：图片消息进 LLM（多模态输入）

- [x] **位置**：`src/event.rs`（图片段提取）、`src/business.rs` + `src/main.rs`
  （ctx 透传）、`extensions/_lib/agent.py`（多模态历史）、
  `extensions/chat/plugin.py`（vision 配置）
- **问题**：bot 是盲的——clean_text 剥掉全部 CQ 码，图片段既不进历史也不进 LLM，
  发图问「这是什么」等于对空文本说话；连「[图片]」占位都没有，模型不知道发过图
- **修法**：event.rs 正规提取图片 URL（数组格式 data.url 优先、file 里的 http
  链接兜底；CQ 码格式 url=/file= 参数并反转义 &#44; 等；顺序去重，上限 4 张）
  进 ctx["images"]；agent.py 构造用户消息按 cfg["vision"] 二选一——开启拼
  OpenAI 多模态 content parts（text + image_url），关闭以「[图片]」占位进文本；
  observe 同口径（未触发群消息的图也进历史）。deepseek-chat 不支持识图，
  vision 缺省关，config desc 注明
- **验证**：cargo test：event.rs 双格式提取/转义还原/去重上限单测；
  agent 侧 vision 开关的内容形态测试（parts vs 占位 vs 空消息不进模型）。
  真机识图待换视觉模型后人工复测
- **状态**：✅ 已完成（2026-10-23）：event.rs 新增 extract_images 及单测三件
  （数组/CQ 双格式含 &#44; 转义还原、去重截断到 4 张）；MsgCtx.images 透传，
  ctx 注入 images 列表；agent.py 新增 _user_message 统一构造用户消息
  （respond 与 observe 共用），chat 插件 observe 调用改传 cfg。新增测试
  agent_images_multimodal_or_placeholder 三段断言
- 提交：本次提交

### 3. 权限分级：危险工具门禁

- [x] **位置**：`extensions/chat/plugin.py`（send_message/recall 工具、
  _is_admin/_role_of）
- **问题**：全仓库没有任何权限概念（grep 零命中），而 send_message 接受任意
  chat_id 且已暴露给模型——任何群友一句话就能让 bot 向任意会话发消息、撤回消息，
  是现成的滥用面；框架其他工具（状态/联网/戳一戳）无此风险
- **修法**：私聊默认信任（个人 bot 形态），群聊按 get_group_member_info 的
  role（owner/admin）放行，校验失败按无权限处理（fail closed）并打日志；
  结果缓存 5 分钟（模块级 dict，热重载即丢，只影响命中率不影响正确性）。
  门禁只挡 send_message / recall，poke/react/联网/状态类无害工具不设卡
- **验证**：`just lint` + `cargo test` 全绿（门禁是动作桥上的胶水，
  自动化覆盖到 role 解析的纯函数边界）；真机语义（普通成员触发被拒、
  管理员放行、缓存生效）连 QQ 后人工复测
- **状态**：✅ 已完成（2026-10-23）：chat 插件新增 _is_admin（私聊/自身直通、
  群聊查 role、5 分钟缓存、fail closed）与 _role_of 纯函数（应答 JSON 解析，
  缺失/畸形回空串），send_message / recall 首行门禁，拒绝文案随工具结果
  回给模型转述。真机复测待连 QQ
- 提交：本次提交

## 🟡 中优先级

### 4. 统一帮助系统

- [ ] **位置**：`extensions/*/plugin.py`（元信息声明）、新插件 `extensions/help/`
- **问题**：「帮助」只是 qa 插件自己的关键词列表；用户无从得知 bot 有哪些
  插件/工具/触发词，能力可发现性为零，也是插件生态成熟的前提
- **修法**：插件契约加可选声明 META = {"desc": 一句话, "usage": 触发词说明}；
  新增 help 插件（PRIORITY 靠前）聚合各插件 META 输出总览，支持二级查询
  单个插件的 usage。控制台 `plugins` 顺带打 desc。热重载后新 META 自然生效
- **验证**：三插件声明 META 后 QQ 发「帮助」得到分插件能力总览；「帮助 chat」
  得到 chat 的 usage；禁用插件不出现在总览

### 5. 说话人身份：昵称/群名片注入

- [ ] **位置**：`src/event.rs`（sender 字段透传）、`extensions/_lib/agent.py`
  （历史前缀）、`extensions/chat/plugin.py`（system prompt 附加）
- **问题**：群聊历史只有 `<QQ号>` 前缀，模型不知道对方叫什么，问「我是谁」
  只能报号码；OneBot 11 事件 sender 自带 card/nickname，从未利用
- **修法**：事件链路随 ctx 下发 sender.card/nickname（事件自带字段，无需动作
  往返）；agent.py 群聊历史前缀改「昵称(QQ号)」；respond 时把当轮说话人身份
  行拼进上下文（或 system prompt），私聊同理
- **验证**：群里 @bot 问「我叫什么」，模型用群名片回答；改群名片后新消息
  用新名片（不缓存旧值）

## 🟢 低优先级

### 6. 长期记忆

- [ ] **位置**：`extensions/_lib/agent.py` 或独立插件、`loquat_state` 锚点扩展
- **问题**：history_limit 条数裁剪 + 按会话隔离，跨会话/跨话题的用户事实
  （称呼、偏好、约定）无处沉淀，重启后只剩历史文件里的只言片语
- **修法**：facts 存储（JSON per user，落 data/memory/，复用会话落盘的原子写
  模式）+ remember / recall 两个 agent 工具；respond 时把该用户已记住的事实
  摘要拼进 system prompt。先做显式工具（模型调用读写），自动抽取后置
- **验证**：聊天中说「记住我叫 X」，新开会话问「我叫什么」能答上；重启宿主仍在；
  损坏的记忆文件跳过不拖垮启动

### 7. 群管能力

- [ ] **位置**：新插件 `extensions/groupguard/`（消费 get_group_member_info /
  set_group_ban / delete_msg 动作）
- **问题**：无任何群管姿态：关键词过滤、刷屏警告做不了；入群欢迎依赖
  notice 事件（26102201#7 落地后接入）
- **修法**：关键词命中撤回 + 警告（bot 须为群管理员，NapCat 判定）、
  同 user 短时频次限制；阈值与词表走 SCHEMA 配置。PRIORITY 低于 status
  高于 chat，命中即接管
- **验证**：测试群命中关键词被撤回并警告；普通消息不受影响；bot 非管理员时
  降级为只警告不撤回
