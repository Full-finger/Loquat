### 2. agent 会话历史持久化

- [x] **位置**：`src/pybridge.rs:67`（loquat_state 锚点）、`extensions/_lib/agent.py:21`（sessions dict）
- **问题**：会话历史只活在进程内存，重启即丢。机器人常驻聊天场景，重启（部署、崩溃恢复、
  改配置）后所有群的上下文清零，模型失忆
- **修法**：宿主退出或定时把 sessions 落盘（JSON per chat，放 `data/sessions/`），
  启动时回填锚点 dict。写入时机选 worker 空闲或每 N 条，不引入阻塞；格式带版本号防后续演进踩格式
- **验证**：聊几轮建立上下文 → 重启宿主 → 同会话追问上下文相关问题，模型能接上；
  损坏的会话文件跳过并记日志，不影响启动
- **状态**：✅ 已完成（2026-10-22）
  - 落盘：每次历史变化后写 `data/sessions/<message_type>_<chat_id>.json`
    （respond 收尾与 observe 各一处，覆盖全部写入点）；先写 .tmp 再 os.replace
    原子替换；OSError 只告警不断链。不做退出时落盘——每条消息后已落，
    退出路径零新增
  - 回填：宿主启动时 pybridge::load_sessions() 跑内嵌 Python 遍历目录，
    校验 version==1 与文件名格式，损坏/版本不符计数跳过（单文件原因走 stderr，
    汇总走统一日志）；在锚点就位后、业务加载前完成
  - persist_dir 每次从锚点读（运行时可改），配套 set_persist_dir 供测试
    指临时目录，已有 5 个 agent 测试全部隔离
  - 新增测试 agent_sessions_persist_to_disk_and_reload：落盘内容（版本号+消息）、
    清内存后回填、坏文件跳过计数，三段全覆盖
  - 已验：`just lint` 全绿、`cargo test` 22 通过；本机实跑空历史静默启动。
    聊几轮重启接上下文的端到端待连接 QQ 后人工复测

### 4. 群聊 @机器人 消息段正规解析

- [x] **位置**：`extensions/chat/plugin.py:81`（`"[CQ:at,qq=...]" in raw` 字符串包含判断）、
  `src/main.rs:82`（parse_incoming 只取 raw_message）
- **问题**：mvp.md 明言「往后放」的点。现在靠 CQ 码字符串匹配，OneBot 数组格式消息段
  （`message` 为 list 而非 string）一来判断失效；`self_id` 也未校验（被 at 其他人时
  只要码串相符就误触发）
- **修法**：parse_incoming 时解析 message 段（string 按 CQ 码切，list 按 type==at 遍历），
  在 ctx 布尔字段 `is_at_bot`（校验 qq == self_id）下发；chat 插件删本地判断改读字段
- **验证**：数组格式消息注入（构造 OneBot 事件）正确判定 at 与否；群里 at 其他成员
  不误触发机器人
- **状态**：✅ 已完成（2026-10-22）
  - 事件解析拆为 src/event.rs：parse_incoming 支持 message 段数组（消息段 list，
    qq 兼容数字/字符串）与 CQ 码字符串两种格式，字段缺失退化用 raw_message；
    校验 qq == self_id，at 别人/全体（qq=all）不误触发
  - ctx 新增 is_at_bot 布尔字段下发；chat 插件删本地字符串判断改读字段
  - 新增 4 个单测：CQ 码精确匹配（含 qq=1001 不误判 100、qq=all 排除）、
    数组格式数字/字符串 qq、整链双格式判定、机器人自身消息丢弃
  - 已验：`just lint` 全绿、`cargo test` 21 通过；真实群聊 at 触发待连接 QQ 后
    人工复测
- 提交：本次提交

    对触发消息回应）
